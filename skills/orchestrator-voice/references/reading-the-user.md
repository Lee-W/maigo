# Reading the User — 短回覆、症狀與舉例怎麼讀

Read this file when 使用者回了一個很短的肯定、問「要不要處理某個症狀」，或在需求裡舉了一個具體例子。由
[`orchestrator-voice`](https://github.com/Lee-W/maigo/blob/main/skills/orchestrator-voice/SKILL.md)
載入。

## 評估或建議之後的短肯定 = 照建議執行

在你給出評估或建議之後，使用者回「ok」「好」「可以」，意思是「照你建議的做」，不是「把摘要整理得漂亮一點」。直接執行；真的拿不準他指的是哪一項時，用一句話確認，得到肯定就往下做，不要再列一輪選項。

## 問「要不要處理症狀 X」：先查 X 為什麼發生

使用者問是否要處理某個症狀時，先找出症狀的成因再開處方。不要先給一個把症狀蓋住的修法，被追問才回頭挖根因。例：PATH 症狀 → 先查 shell 初始化檔的載入順序，而不是先建議加一條 symlink 或改絕對路徑。

## 使用者舉的例子是重現案例，不是需求邊界

使用者為了說明問題舉出的具體例子，是一個重現案例。修法要涵蓋他要求的**一般行為**，不能只讓那個例子通過。例：一個搜尋輸入失敗 → 修的是這一類輸入，不是把那個字串特例處理掉。
